# 공개 캡처로 반증 조건 시험하기

설계 §10 의 첫 반증 조건은 이것이다 — *"공개 ICS 캡처에서 `UNDECIDABLE` 비율이 압도적이면
Modbus 단독으로 유의미한 판정이 된다는 전제가 틀린 것"*. 내려받기만 하고 실행하지 않으면
이 조건은 한 번도 시험되지 않으므로, **실제로 돌린 결과를 여기 적는다.**

## 하는 법

```bash
bash scripts/fetch-samples.sh          # 또는  pwsh scripts/fetch-samples.ps1
mvn -DskipTests package
java -Dstdout.encoding=UTF-8 -jar cli/target/huginn.jar \
    samples/4SICS-GeekLounge-151022.pcap samples/4SICS-GeekLounge-151022-policy.yaml
```

`editcap`(Wireshark)이 필요하다 — 배포본이 pcapng 이면 `PcapReader` 가 거부하므로 스크립트가
pcap 으로 정규화한다(2026-09-05 현재 세 파일 모두 이미 pcap 이라 변환은 일어나지 않는다).
캡처 자체는 커밋하지 않는다. 해시는 `SHA256SUMS` 에 기록돼 있다.

캡처 출처: **4SICS ICS Lab**, Netresec 배포 — 재배포·교육 사용 시 **CS3Sthlm** 을 명시해 달라는
것이 배포처의 요청이다. <https://www.netresec.com/?page=PCAP4SICS>

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 151020 | 246,137 | 37,197 | 0 | 7,290 | 0 | 0 | 0 | 0 |
| 151021 | 1,253,100 | 132,406 | 11 | 112,747 | 0 | 11 | 0 | 0 |

151020·151021 의 정책 파일은 선언이 비어 있다(각 캡처에 선언할 Modbus 통신이 없거나 전부
`UNDECIDABLE` 이라 판정에 쓰이지 않는다). 151022 의 정책은 폴러 → PLC 세 대의 **읽기만**
선언했다 — 전부 선언하면 위반이 0 건이라 대사가 실제로 도는지 알 수 없다.

151022 의 위반 내역: **HIGH 20,980**(선언되지 않은 쓰기 — 같은 폴러가 읽기만 선언돼 있다)
· **MEDIUM 48**(미등록 호스트 `192.168.2.44`·`192.168.2.133` 의 읽기 12·9 건, 그리고 폴러가
선언되지 않은 PLC `.50`·`.100`·`.20` 을 읽은 27 건).

## 판정

**반증되지 않았다 — 단, 조건부다.**

- **`UNDECIDABLE` 비율은 압도적이지 않다.** 151022 에서 관찰 49,767 건 중 `UNDECIDABLE` 은
  48 건(**0.1%**)이다. 판정 불가 대화는 Modbus 대화 80 개 중 24 개(30%)로 적지 않지만, 그
  대화들이 나르는 트래픽은 무시할 만하다 — 폴링 대화 셋이 관찰의 99.9% 를 만든다.
- **그러나 데이터셋의 Modbus 비중 자체가 얇다.** 4SICS 랩은 S7comm 중심이다 — 151020 은
  Modbus 가 **한 프레임도 없고**(전량 S7comm·DNS·ARP), 151021 은 19 패킷뿐이다. "Modbus
  단독으로 유의미한가" 는 **151022 하나로만 시험됐다.** 세 캡처짜리 표를 근거로 일반화하지 않는다.
- **151021 이 드러낸 진짜 비용은 `UNDECIDABLE` 비율이 아니라 FC 43 이다.** 그 캡처의 Modbus 는
  전량 FC 43(Read Device Identification)이고, `192.168.2.42` 가 PLC 여섯 대를 차례로 두드리는
  **장비 열거 스캔**이다. 설계 §5 대로 FC 43 은 `UNDECIDABLE` 이라 이 스캔은 Finding 이 되지
  않고 "`UNDECIDABLE` 관찰 11" 이라는 수치로만 남는다. MEI 타입을 읽으면 MEI 14 를 READ 로
  분류해 잡을 수 있다 — 2 차에서 다룰 값이 이것으로 하나 늘었다.
- **하지 않는 것이 하나 더 드러났다.** 리포트는 `UNDECIDABLE` 을 **세기만 하고 어느 대화였는지
  적지 않는다.** 151021 에서 무엇이 판정 불가였는지 알아내려면 tshark 를 따로 돌려야 했다.

## 독립 검증 (tshark 4.6.8)

같은 캡처를 Wireshark 의 Modbus 해석기와 대조했다. **Huginn 은 포트를 보지 않고 프레이밍으로
판정하고 tshark 는 502 포트 기준으로 해석하므로, 둘이 맞으면 서로가 서로의 반증 시도가 된다.**

| 대조 | tshark | Huginn | |
|---|---:|---:|---|
| 151020 총 프레임 | 246,137 | 246,137 (처리 패킷) | 일치 |
| 151020 비TCP·비IPv4 (ARP 4,389 + loop 2,481 + UDP 27,587 + ICMP 2,740) | 37,197 | 37,197 (대상 외 패킷) | 일치 |
| 151022 Modbus 요청 패킷 (`mbtcp && tcp.dstport==502`) | 49,767 | 49,767 (관찰 총수 = 위반 21,028 + 허용 28,691 + UNDECIDABLE 48) | 일치 |
| 151022 요청 함수코드 → READ (FC 1·2·3·4) | 28,712 | 28,739 | 27 차이 |
| 151022 요청 함수코드 → WRITE (FC 5·6·15·23) | 20,979 | 20,980 | 1 차이 |
| 151022 FC 43 | 24 | (UNDECIDABLE 로 계수) | 설계대로 |

`mbtcp` 응답 패킷 49,787 건은 Huginn 이 **하나도 관찰하지 않았다** — 설계 §5-⑤("요청만
`Observation` 이 된다")가 실제 트래픽에서 지켜졌다는 뜻이다. 총수가 정확히 맞는데 READ/WRITE
분류에서 28 건이 갈리는 것은 한 TCP 세그먼트에 MBAP 프레임이 여러 개 실린 경우를 두 도구가
다르게 세기 때문으로 보인다(tshark 는 패킷, Huginn 은 프레임). **아직 끝까지 파고들지 않았다.**

**502 가 아닌 포트의 Modbus 는 이 데이터셋에 없었다** — Huginn 이 찾은 위반 21,028 건의 목적지
포트는 전부 502 다. 비표준 포트 우회 탐지는 합성 캡처(`EndToEndTest.비표준_포트의_우회를_잡는다`)
로만 증명돼 있고 **실캡처로는 아직 시험되지 않았다.**
